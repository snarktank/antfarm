## Codebase Patterns

### Directory Structure
- Workflows live in `workflows/<workflow-name>/`
- Each workflow has an `agents/` subdirectory with one folder per agent
- Each agent folder contains at least a SOUL.md file

### Agent SOUL.md Format
SOUL.md files follow this structure:
```markdown
# <Agent Name> - Soul

You're a [role description]. [Core job description]

## Personality
[Character traits and approach]

## How You Work
[Concrete work process, typically bullet points]

## Communication Style
[How the agent communicates findings/results]

## What You Care About
[Core values and priorities]
```

### Workflow.yml Structure
Required top-level fields:
- `id`: kebab-case workflow identifier
- `name`: Human-readable workflow name
- `version`: Numeric version
- `description`: Multi-line description of what the workflow does
- `agents`: Array of agent definitions
- `steps`: Array of workflow steps (can be empty for skeleton)

Agent definitions require:
- `id`: Agent identifier
- `name`: Human-readable agent name
- `role`: Agent role type (coding, verification, analysis, etc.)
- `description`: What the agent does
- `workspace`: Object with `baseDir` and `files` mapping

### Testing Patterns
- Tests live in `tests/` directory
- Use Node.js native test runner (`node:test`)
- Import assertions from `node:assert/strict`
- Test file names follow pattern: `<feature>.test.ts`
- Test structure: describe blocks with it tests
- Use yaml package to parse workflow.yml files in tests
- Import from `dist/` not `src/` (compiled output)

### Workflow Library Code
- Workflow-specific TypeScript code goes in `src/lib/<workflow-name>/`
- This ensures it's compiled by the build process (tsconfig includes `src/**/*.ts`)
- Tests import from `dist/lib/<workflow-name>/*.js`
- Agent SOUL.md files document the API and usage patterns

### Auto-Detection Router Pattern
- Use a router module to auto-detect input format and route to appropriate handler
- Router should check file extension and validate file existence
- Return unified output interface regardless of input format
- Include descriptive error messages for unsupported formats
- Log which extraction method was used (aids debugging)
- Example: document-router.ts detects markdown vs Word and unifies output
