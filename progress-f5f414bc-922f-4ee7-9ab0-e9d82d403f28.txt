## Codebase Patterns
- `src/db.ts` uses in-place idempotent migrations: create base tables with `CREATE TABLE IF NOT EXISTS`, then add newly introduced columns by probing `PRAGMA table_info(...)` and applying guarded `ALTER TABLE ... ADD COLUMN`.
- DB migration tests should isolate `os.homedir()` by setting `process.env.HOME` and importing `dist/db.js` dynamically with a cache-busting query string.
- Structured planner payloads in step output are parsed as multi-line `KEY_JSON:` blocks up to the next `KEY:` boundary (see `collectJsonBlock` in `src/installer/step-ops.ts`).
- Service-layer domain errors in installer flows should be deterministic via typed error codes (e.g., `ScopeFreezeError.code`) so retry/verify logic can assert behavior without fragile message matching.
- Loop-scope policy enforcement should run in both claim-time (`claimStep`) and continuation-time (`checkLoopContinuation`) paths to avoid silent out-of-scope progression between iterations.
- CLI machine-readable commands in this repo should prefer line-oriented `key=value` output and typed error codes on stderr for script-safe parsing.
